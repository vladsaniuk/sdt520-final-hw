**Status:** ✅ SHIPPED 2026-05-10

## Overview

Brownfield completion of a hollow scaffold — FastAPI + React + Neo4j + Docker Compose existed but chat returned mock data, ingestion was a stub, and the frontend wouldn't compile. Delivered: real LLM chat, document ingestion, multi-turn conversation, Terraform download, and zero-setup Docker Compose experience. Core design decision: recommendations grounded solely on user-uploaded documents (not hardcoded seed data).

## Milestone Summary

**Decimal Phases:**
- Phase 2.1: UI Polish & Visual Design (inserted after Phase 2 for UX quality before chat wiring)

**Key Decisions:**
- Recommendations grounded solely on user-uploaded documents — hardcoded AWS seed data (GRAPH-01/02/03) descoped from advisor pipeline. The seed.py and `/api/v1/seed` endpoint remain for manual use but do not influence LLM output.
- sentence-transformers (local, 384-dim all-MiniLM-L6-v2) used for embeddings — no separate OpenAI embeddings API key required
- Terraform validate runs inside Docker container (terraform CLI installed in backend Dockerfile)
- SSE/streaming deferred to v2 — structured JSON response used for v1 chat

**Issues Resolved:**
- mermaid.contentLoaded() removed in v10+ — replaced with mermaid.run()
- TypeScript bool→boolean in CostTable.tsx
- Dead SQLAlchemy/psycopg2 code removed
- Mid-file imports causing runtime crashes fixed
- CORS wildcard replaced with env-var-driven origin list
- git negation gotcha: whole-dir ignore blocks negation — fixed with glob pattern + .gitkeep chain

**Technical Debt Incurred:**
- Conversation history is in-memory (dict keyed by conversation_id) — lost on restart; v2 should persist to Neo4j
- No authentication — demo tool only; v2 if multi-user needed
- seed.py and /api/v1/seed endpoint exist but are unused by the advisor — can be removed or repurposed in v2
