## Component Specs

### 1 — Context Fill Bar

**Location:** Inside the input area (`ChatBox.tsx`), between the textarea/send row and the
"Shift+Enter for new line" hint text. Full-width, constrained to `maxW="3xl" mx="auto"` same
as the textarea row.

**Visual design:**

```
[ ████████████░░░░░░ 42%  Context ]
```

- Outer container: `HStack spacing={2}` with `w="full"` aligned to `maxW="3xl" mx="auto"`
- Progress track: `Box h="4px" flex={1} bg="gray.200" borderRadius="full"`
- Fill bar: `Box h="4px" w="{fill}%" bg="{color}" borderRadius="full" transition="width 0.3s ease"`
- Label: `Text fontSize="11px" color="{color}" fontWeight="medium" flexShrink={0}` — content: `"{N}%"`
- Separator label: `Text fontSize="11px" color="gray.400" flexShrink={0}` — content: `"Context"`
- Container `mt={1}` (4px below send row), `mb={1}` (4px above hint text)

**States:**

| State | Bar color | Label color | Condition |
|-------|-----------|-------------|-----------|
| Healthy | `green.400` | `gray.500` | fill < 75% |
| Warning | `aws.orange` | `aws.orange` | 75% ≤ fill < 90% |
| Critical | `red.500` | `red.500` | fill ≥ 90% |
| Zero / unknown | bar hidden, label hidden | — | No messages yet (welcome screen) |

**Behavior:**
- Hidden on welcome screen (messages.length === 0)
- Pre-send: estimate updates live as user types using character approximation:
  `estimate_tokens ≈ Math.ceil(totalHistoryChars / 4)`. Model max = 128,000 tokens (gpt-4o).
  `fillPercent = Math.min(Math.round((estimatedTokens / 128000) * 100), 100)`
- Post-send: update from `response.usage.prompt_tokens` if present in API response
- Width transition: `transition="width 0.3s ease"` for smooth animation
- No tooltip needed — the % label is always visible

**No new component needed** — implemented inline in `ChatBox.tsx`.

### 2 — Warning Banner (Context Overflow)

**Location:** In the `ChatBox.tsx` render tree, between the message list and the input area.
Same slot as the existing error Alert. Shown when `fillPercent >= 75` AND not dismissed.

**Visual design:**

```
┌─────────────────────────────────────────────────────────┐
│ ⚠  Context window is 75% full                           │×│
│    Older context may be dropped on the next message.    │
│    [Compact]  [Clear]                                   │
└─────────────────────────────────────────────────────────┘
```

- Chakra `Alert` component: `status="warning"` with custom overrides:
  `bg="orange.50" borderRadius="lg" border="1px solid" borderColor="orange.300" mx={4} mb={3}`
- `AlertIcon` with `color="orange.500"`
- `VStack align="flex-start" spacing={1} flex={1}`:
  - Heading: `Text fontSize="sm" fontWeight="semibold" color="gray.800"` — see Copywriting
  - Body: `Text fontSize="13px" color="gray.600"` — see Copywriting
  - CTA row: `HStack spacing={2} mt={1}`:
    - Compact: `Button size="xs" bg="aws.orange" color="aws.squid" fontWeight="bold" _hover={{bg:"aws.orangeDark"}}` → label: "Compact"
    - Clear: `Button size="xs" bg="red.100" color="red.700" fontWeight="semibold" _hover={{bg:"red.200"}}` → label: "Clear history"
- `CloseButton` aligned `alignSelf="flex-start"` at top-right

**States:**

| State | Condition |
|-------|-----------|
| Hidden | `fillPercent < 75` OR `dismissed = true` |
| Visible | `fillPercent >= 75` AND `dismissed = false` |
| Re-shown | Dismissed state resets when fill drops below 75% (i.e., after Clear/Compact) |

**Behavior:**
- Dismissing (×) sets `warningDismissed = true` in component state
- Dismissed state resets automatically when fill drops below threshold again
- Clicking "Compact" triggers the compact flow (separate spec below)
- Clicking "Clear history" triggers the clear flow (separate spec below)
- Banner does NOT replace the existing error Alert — both can coexist (warning above, error below, or stacked)

### 3 — Compact Control

**Location:** In `App.tsx` sidebar, below the conversation list VStack, above the footer nav
`Box`. A compact controls row with both Compact and Clear buttons side-by-side.

**Visual design (sidebar controls row):**

```
─── sidebar controls ──────────────────────
│  [⊟ Compact]          [✕ Clear history] │
────────────────────────────────────────────
```

- Wrapper: `HStack px={3} py={2} spacing={2} borderTop="1px solid" borderColor="aws.squidLight"`
- Compact button: `Button leftIcon={<Icon as={MdCompress} />} size="sm" variant="ghost"
  color="gray.300" _hover={{bg:"aws.squidLight", color:"white"}} flex={1} justifyContent="center"
  fontSize="xs" fontWeight="semibold"` — label: "Compact"
- Uses icon `MdCompress` from react-icons/md (available in package, no new dep)

**States:**

| State | Visual |
|-------|--------|
| Default | Ghost, `gray.300` text, transparent bg |
| Hover | `aws.squidLight` bg, `white` text |
| Loading (compact in progress) | `isLoading` spinner replaces icon, button disabled |
| Disabled (no messages / empty conv) | `color="gray.600"` cursor not-allowed, `isDisabled` |

**Behavior:**
- Always visible (persistent)
- Disabled when `messages.length === 0`
- On click: calls backend compaction endpoint (POST /api/v1/chat/compact or equivalent), shows
  loading spinner on button, on success replaces history with compacted summary, hides warning
  banner (fill will drop), shows success toast: "Conversation compacted" (status: success,
  duration: 3000ms, position: bottom)
- On error: shows error toast: "Compact failed — please try again." (status: error, duration:
  4000ms, position: bottom)
- No confirmation dialog — action is reversible via new conversation

### 4 — Clear Control

**Location:** Same sidebar controls row as Compact (see above). Right side.

**Visual design:**

- Clear button: `Button leftIcon={<Icon as={MdClear} />} size="sm" variant="ghost"
  color="red.300" _hover={{bg:"red.900", color:"red.200"}} flex={1} justifyContent="center"
  fontSize="xs" fontWeight="semibold"` — label: "Clear"
- Uses icon `MdClear` from react-icons/md (already available)

**States:**

| State | Visual |
|-------|--------|
| Default | Ghost, `red.300` text, transparent bg |
| Hover | `red.900` bg, `red.200` text |
| Disabled (no messages) | `color="gray.600"`, `isDisabled` |

**Behavior:**
- Always visible (persistent)
- Disabled when `messages.length === 0`
- On click: shows inline confirmation row **replacing** the button (no modal):
  - `Text fontSize="xs" color="gray.300"` — "Clear all messages?"
  - `Button size="xs" colorScheme="red"` — "Yes, clear"
  - `Button size="xs" variant="ghost" color="gray.400"` — "Cancel"
- On confirm: clears message history in frontend state, clears localStorage history for
  current `conversation_id`, sends `conversation_id` retained (same session, fresh context),
  resets fill to 0%, hides warning banner, shows welcome screen. No backend call needed —
  history is wiped client-side; next message starts fresh server-side conversation.
- On cancel: restores the Compact/Clear button row

### 5 — Diff Badge

**Location:** On assistant response bubbles, immediately below the text bubble `Box` and
above the MermaidViewer (if present). Shown only when there is a previous assistant response
to diff against (i.e., not on the first assistant message).

**Visual design:**

```
┌──────────────────────┐
│ Thinking...          │    ← assistant bubble text
└──────────────────────┘
  [+ECS] [+Lambda] [−EKS]   ← diff badges row (below bubble)
```

- Wrapper: `HStack spacing={1} mt={1} flexWrap="wrap"`
- Each added service: `Tag size="sm" borderRadius="md" bg="green.100" color="green.700"
  fontWeight="semibold" fontSize="11px" px={2} py={0}` — content: `"+{ServiceName}"`
- Each removed service: `Tag size="sm" borderRadius="md" bg="red.100" color="red.700"
  fontWeight="semibold" fontSize="11px" px={2} py={0}` — content: `"−{ServiceName}"` (use
  Unicode minus `−` U+2212, not ASCII hyphen)
- If no diff (identical services or first response): diff badge row is not rendered (zero height)
- Maximum services shown: all changed services (no truncation — AWS service names are short)

**States:**

| State | Behavior |
|-------|----------|
| First assistant message | No badge row rendered |
| Subsequent with changes | Badge row rendered with add/remove tags |
| Subsequent, no changes | No badge row rendered |
| Services list empty in response | No badge row rendered |

**Behavior:**
- Diff computed in frontend: compare `currentMsg.services.map(s=>s.name)` vs
  `previousAssistantMsg.services.map(s=>s.name)`
- Added = in current but not in previous
- Removed = in previous but not in current
- Pure display element — no interaction, no click handler
- `services` field comes from the structured `ArchitecturePlan` API response

### 6 — Error Bubble (in thread)

**Location:** In the message thread `VStack`, at the position where the failed assistant
response would have appeared. Rendered as a special `role: 'error'` message (extend `Message`
interface).

**Visual design:**

```
┌─────────────────────────────────────┐
│ ⚠  Failed to generate plan          │
│    The advisor couldn't process your│
│    request. Please try again.       │
└─────────────────────────────────────┘
```

- Positioned like an assistant bubble (left-aligned, with bolt avatar)
- Avatar: existing `aws.orange` bolt avatar (same as assistant)
- Bubble `Box`: `bg="red.50" border="1px solid" borderColor="red.200" borderRadius="2xl"
  borderTopLeftRadius="sm" px={4} py={3} boxShadow="sm"`
- Inner `HStack spacing={2} align="flex-start"`:
  - `Icon as={MdWarning} color="red.500" boxSize={4} flexShrink={0}`
  - `VStack spacing={0} align="flex-start"`:
    - `Text fontSize="sm" fontWeight="semibold" color="red.700"` — heading
    - `Text fontSize="sm" color="red.600" lineHeight="relaxed"` — body

**States:**

| State | Condition |
|-------|-----------|
| Visible | Structured output parse failed after retry (D-19/D-20) |
| Not shown | Standard errors (network failure) — those use the existing inline error Alert |

**Behavior:**
- Error bubble is persisted in `messages` state array so it appears in scroll history
- Also triggers a Chakra `toast` simultaneously (see Copywriting)
- Icon `MdWarning` from react-icons/md (already available)
- No retry button in the bubble — user re-sends manually

### 7 — Conversation Session List (Real, replaces mock)

**Location:** Replaces `MOCK_CONVERSATIONS` in `App.tsx` sidebar VStack.

**Visual design:** Identical to existing mock session rows. No visual changes — only the data
source changes from static mock to real state.

```
[active bg: aws.squidLight]
│ Serverless e-commerce API   │  ← title (first user message, max 32 chars, ellipsis)
│ 5 turns · 2m ago            │  ← subtitle: turn count + relative time
```

- Title: `Text fontSize="sm" color="gray.200" fontWeight="medium" noOfLines={1}` — first user
  message truncated at 32 characters with ellipsis (Chakra `noOfLines={1}` handles this)
- Subtitle: `Text fontSize="11px" color="gray.500" noOfLines={1}` — `"{N} turn{s} · {relTime}"`
- Timestamp: removed as a separate line — merged into subtitle for space efficiency
- Active indicator: `bg="aws.squidLight"` (same as current mock)
- Hover: `_hover={{bg: activeConv === c.id ? "aws.squidLight" : "whiteAlpha.100"}}`

**Empty state (no conversations yet):**
- `Text px={2} pt={2} fontSize="11px" color="gray.600" fontStyle="italic"` —
  "No conversations yet. Send your first message."
- Remove the old placeholder `"Full history available in Phase 3"` text

**"New conversation" button behavior:**
- Generates a new `conversation_id` (UUID), clears message state, resets fill, adds new empty
  session to session list, navigates to chat page
- Session list immediately shows the new (empty) session as active

**Session limit display:** All sessions shown (unlimited per D-01). Sidebar scrolls if more
than ~8 sessions fill the space.

## Implementation Notes for Executor

1. **`Message` interface extension** — Add `role: 'error'` variant and optional `diff?: {added: string[], removed: string[]}` field to support diff badges and error bubbles without breaking existing render logic.

2. **`fillPercent` state** — Single `number` state in `ChatBox.tsx`, updated (a) live on input change via character approximation and (b) from `response.usage.prompt_tokens` post-send. Drives both the context fill bar color and the warning banner visibility.

3. **`warningDismissed` state** — `boolean`, resets to `false` when `fillPercent` drops below 75 (after compact or clear).

4. **Sidebar controls row** — New `HStack` inserted in `App.tsx` sidebar between the conversations VStack and the footer nav Box. Compact/Clear receive callbacks from App state (the conversation state lives in App, not ChatBox).

5. **Session list state** — `conversations: ConversationSession[]` in App.tsx replaces `MOCK_CONVERSATIONS`. Each session: `{ id, title, turnCount, updatedAt }`. Updated on each sent message via callback from ChatBox.

6. **`conversation_id` in localStorage** — Key: `"aws-advisor-conversation-id"`. Persisted on first response from server. Cleared on "Clear" action. New session generates new UUID client-side (or accepts server-assigned UUID from first response).
